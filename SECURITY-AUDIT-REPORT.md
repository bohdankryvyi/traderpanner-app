# Public repo secrets & sensitive data — audit report

**Date:** 2025-02-17  
**Scope:** app-backend/, app-frontend/, e2e/, .github/, root files  
**Goal:** Safe to make repo public; no secrets, tokens, or credentials committed.

---

## 1. Findings

### A) Hardcoded secrets

- **No real API keys or tokens found.** Searched for:
  - `OPENAI_API_KEY`, `ALPHAVANTAGE_API_KEY`, `DB_PASSWORD`, `password=`, `api_key`, `secret`, `token`, `bearer`, `authorization`, `BEGIN RSA`, `BEGIN OPENSSH`
  - Patterns like `sk-...`, `ghp_...`, long hex strings
- **References are safe:** Env var names and placeholders only (e.g. `System.getenv("OPENAI_API_KEY")`, README `"<your-openai-key>"`).
- **Default DB password** `trader` appears in:
  - `application.yml` as `${DB_PASSWORD:trader}` (default for local dev)
  - Root `.env.example` and CI workflow (intentional local/CI default; documented as dev-only).
- **No** `.env`, `*.pem`, `*.key`, `*.p12`, `*.jks`, `*.keystore` committed. No real emails, phone numbers, or addresses found.

### B) .gitignore

- **Root:** Had `.env` and `logs/*.log` but was missing:
  - Explicit allow for `.env.example`
  - `e2e/playwright-report/`, `e2e/test-results/`, traces, videos, screenshots
  - `backend.log`, `frontend.log`, `*.pid` at repo root and in app-* dirs
- **app-frontend:** Did not ignore `.env` / `.env.local`; added with explicit allow for `.env.example`.
- **Tracked artifact:** `e2e/playwright-report/index.html` is currently **tracked**. It is generated by Playwright and should not be in version control (no secrets in it; it’s HTML/JS). See “Remaining steps” below.

### C) Example env files

- **Root `.env.example`:** Contained real-looking placeholder `DB_PASSWORD=trader` (intentional local default). Added header comment: “Copy to .env”, “NEVER commit .env or real keys”, and “local dev only” for DB.
- **app-frontend/.env.example:** Only `VITE_API_BASE_URL=http://localhost:8080`. Added “Do not commit .env” comment. No keys.

### D) README & docs

- README used placeholder `"sk-..."` for OpenAI key. Replaced with `"<your-openai-key>"` and added explicit “never commit keys” and “do not commit .env” in Environment variables and Running AI sections.
- Instructions already use `$env:OPENAI_API_KEY` (PowerShell); strengthened to say “use your own key; never commit it” and “Never commit keys.”

### E) GitHub Actions

- **No secrets printed.** Workflow uses `OPENAI_API_KEY: ""` and `ALPHAVANTAGE_API_KEY: ""` (empty literals). No step echoes env vars.
- **DB_PASSWORD: trader** is a CI-only default for the Postgres service container; acceptable for public E2E.
- Added a short comment above “Upload logs” that app logs do not log API keys (keys come from env and are not printed).

### F) Logs / artifacts

- Backend does **not** log `Authorization` or API keys (OpenAiClient only logs model, message count, status, content length, and `e.getMessage()`).
- Uploaded artifacts: `backend.log`, `frontend.log`, Playwright report. No secrets are written to these in normal operation. Comment added in workflow.

### G) Git history

- **No evidence of past commits of real secrets** from the current scan of tracked files. No `sk-` or `ghp_` patterns in code or docs.
- **If you ever committed a real key in the past:** Treat history as potentially compromised. Do **not** rely only on removing the key in the latest commit. Recommended:
  1. Rotate all keys (OpenAI, Alpha Vantage, DB if applicable).
  2. Rewrite history to remove the secret: e.g. `git filter-repo` or BFG Repo-Cleaner, then force-push (coordinate with all clones).
  3. Document in this report or in a security runbook that keys were rotated and history was cleaned.

## 3. Remaining risks / next steps

1. **Untrack Playwright report**  
   Applied in this audit: `e2e/playwright-report/` was removed from tracking via `git rm -r --cached e2e/playwright-report`. It is now in `.gitignore` so future runs won’t add it. No secrets were in this artifact.

2. **Optional: redact error bodies in backend**  
   `OpenAiClient` throws with `response.body()` in the message on non-200. If you ever log that exception message, consider truncating or redacting the body (e.g. strip or mask) to avoid leaking provider error payloads.

3. **If history ever contained secrets**  
   Rotate all affected keys and clean history with `git filter-repo` or BFG; document rotation and cleanup.

4. **Pre-commit / CI (optional)**  
   Consider a pre-commit hook or CI step that fails on patterns like `sk-`, `ghp_`, or `BEGIN RSA PRIVATE KEY` in staged/tracked files.
